# TAGO 디자인 명세 (평평한 카드 · 큰 버튼 · 승차권/노선)

KTX 승차권 예매 서비스의 시각 언어. 목표는 "승차권을 사는 도구처럼 보이고, 한 화면에서 한 가지 일만 하게" 만드는 것이다.

## 한 줄 컨셉
**평평하고 큼직한 모바일 앱 감각 + 승차권/노선 모티프.** 회색 바탕 위에 흰 카드, 그림자·테두리 없음, 큰 둥근 버튼, 회색 채움 입력창. 출발→도착은 항상 노선 라인(RouteLine).

## 출처와 사용 범위 (중요)
- 토스 TDS 가 **공개한 디자인 원칙·컴포넌트 패턴**(평평한 카드, 큰 버튼의 fill/weak 두 종류, 회색 채움 입력창, 리스트 행, 하단 고정 CTA, 어두운 토스트, 다이얼로그 왼쪽 버튼 "닫기")을 참고했다.
- **사용하지 않는 것:** `@toss/tds-*` 패키지, 앱인토스 UI Kit(Figma), Toss Product Sans·Tossface 폰트, 토스 로고·브랜드 자산, 토스의 hex 팔레트. 토스 문서는 TDS 사용 허가를 "앱인토스 서비스를 제공하기 위한 제한적인 권한"으로 한정하고, UI Kit 라이선스는 다른 서비스에서의 사용·복사·수정을 금지한다. 이 서비스는 앱인토스 서비스가 아니므로 위 자산들은 쓰지 않고, **모든 토큰 값은 이 서비스의 자체 값**이다.
- 이전 디자인(승차권/노선 + 그림자 카드)은 백업 `~/Documents/TAGO-ui-backup-2026-11-20/`에 있다.

## 공통 부품 (`index.css`에 이미 있음 — 다시 만들지 말고 재사용)
- `.ui-btn` + `--lg`(56px) / 기본(48px) / `--sm`(36px), 변형 `--weak`(연한 파랑) `--neutral`(회색) `--danger`, `--block`(전체 폭). 눌림: `scale(.98)`.
- `.ui-card`: 평평한 흰 카드. 테두리·그림자 금지.
- `.ui-field` > `.ui-field__label` + `.ui-field__control`(+ `__help`, `__error`): 회색 채움 입력창, 포커스 시 파란 테두리, 오류는 `aria-invalid="true"` + 아래 오류 문구.
- `.ui-row`(+ `--tap`) `__main` `__title` `__sub` `__right`: 리스트 행.
- `.ui-segment`: 회색 트랙 + 흰 선택 칸(탭/편도·왕복/필터).
- `.ui-bottom-cta`: 모바일 하단 고정 큰 버튼 영역.
- `.ui-title` `.ui-heading`, `.chip`(작은 둥근 사각형), `.ticket`(평평한 승차권, 절취선 유지), `RouteLine`, `.num`, `.sr-only`.

## 규칙
1. **카드는 평평하게.** 흰 카드 + 회색 바탕, 테두리·그림자로 구분하지 않는다. 구분이 필요하면 간격이나 얇은 회색 선.
2. **한 화면 한 가지 일.** 가장 중요한 버튼 하나를 크게(lg), 나머지는 weak/neutral.
3. **버튼은 크고 둥글게.** 주요 버튼 56px, 모바일에서는 하단 고정(`.ui-bottom-cta`) 또는 전체 폭.
4. **입력창은 회색 채움**, 라벨은 위에 항상 보이게, 오류는 필드 바로 아래.
5. **시각이 주인공**: 출발·도착 시각과 요금을 가장 크게(`--text-time-*`, `.num`).
6. **색만으로 상태를 구분하지 않는다.** 칩 텍스트 병행.
7. 이모지 금지(인라인 SVG). 터치 영역 44px 이상. 대비 4.5:1.
8. 모션은 절제: 눌림 `scale(.98)`, 전환 120~200ms, `transform/opacity`만, reduced-motion 존중(전역 처리됨).
9. 반응형 375/768/1024/1440, 가로 스크롤 금지(호차 스트립 같은 내부 스크롤 제외).

## 건드리지 않는 것
- 데이터 흐름, API, 상태 관리, 라우팅, 문구의 의미. (문구 톤 변경은 이번 범위가 아니다.)
- JSX 는 표현을 위한 마크업 변경(클래스 교체, 래퍼, 아이콘)까지만.
- 기능 로직이 의존하는 `id`/`name`/이벤트 핸들러/`aria-*`, 그리고 예매 단계(step) 로직·카운트다운·검증·알림 API.

### 도메인 규칙
1. **혼잡도는 항상 글자와 함께**(여유/보통/혼잡/마감 임박/매진 + 잔여석). 막대만으로 뜻을 전하지 않는다. 예측이라고 쓰지 않는다.
2. **노선색은 이름과 함께.** 색 점만 두지 않는다. 노선색은 이 서비스의 자체 값이다.
3. **출발 임박 안내는 실제 시각 기준**으로만. 가짜 긴급성·가짜 카운트다운 금지.
4. **좌석 선택은 제한 시간 밖**, 선점 이후부터 카운트다운(기존 구조 유지).
5. 보조 글자는 13px 이상(국내 서비스의 "10pt 이하 글씨" 불만 반영).
6. 기능이 데이터에 없는 것(정차역 점·선, 혼잡 예측, 좌석 방향)은 만들지 않는다.

### 조사의 한계 (정직하게)
화면 이미지를 직접 보지 못하고 텍스트 설명·보도자료·블로그 기준이다. 공식 이용안내 원문 여러 건은 열리지 않았다. 수치(15% 입석 할인 등)는 비공식 출처라 구현에 쓰지 않았다.
